# Chirpy

A small Twitter-like JSON API written in Go, built while working through the [Boot.dev](https://www.boot.dev) "Learn HTTP Servers in Go" course. Users can sign up, log in, and post short messages called **chirps**.

## Features

- User registration and login, with passwords hashed using Argon2id
- JWT access tokens (valid 1 hour) and refresh tokens (valid 60 days) that can be revoked
- Create, list, fetch, and delete chirps (max 140 characters, with profanity filtering)
- Filter chirps by author and sort them by creation time
- "Chirpy Red" membership upgrades via a Polka payment webhook, authenticated with an API key
- Static file server with a hit counter and an admin metrics page
- PostgreSQL storage, with type-safe queries generated by [sqlc](https://sqlc.dev) and migrations run by [goose](https://github.com/pressly/goose)

## Tech Stack

| Concern        | Library                                                     |
| -------------- | ----------------------------------------------------------- |
| HTTP routing   | `net/http` (Go 1.22+ method/path patterns)                  |
| Database       | PostgreSQL + [`lib/pq`](https://github.com/lib/pq)          |
| Query codegen  | [sqlc](https://sqlc.dev)                                    |
| Migrations     | [goose](https://github.com/pressly/goose)                   |
| Auth           | [`golang-jwt/jwt/v5`](https://github.com/golang-jwt/jwt), [`alexedwards/argon2id`](https://github.com/alexedwards/argon2id) |
| Config         | [`joho/godotenv`](https://github.com/joho/godotenv)         |

## Getting Started

### Prerequisites

- Go (see the version in `go.mod`)
- PostgreSQL
- [goose](https://github.com/pressly/goose): `go install github.com/pressly/goose/v3/cmd/goose@latest`
- [sqlc](https://sqlc.dev), only needed if you change the SQL queries: `go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest`

### 1. Create the database

```bash
createdb chirpy
```

### 2. Configure the environment

Create a `.env` file in the project root:

```env
DB_URL="postgres://<user>:<password>@localhost:5432/chirpy?sslmode=disable"
PLATFORM="dev"
SECRET="<a long random string used to sign JWTs>"
POLKA_KEY="<API key that Polka sends with its webhooks>"
```

| Variable    | Description                                                    |
| ----------- | -------------------------------------------------------------- |
| `DB_URL`    | PostgreSQL connection string                                   |
| `PLATFORM`  | Set to `dev` to enable `POST /admin/reset`                     |
| `SECRET`    | HMAC secret for signing JWT access tokens                      |
| `POLKA_KEY` | Expected API key for `POST /api/polka/webhooks`                |

You can generate a secret with `openssl rand -base64 64`.

### 3. Run migrations

```bash
goose -dir sql/schema postgres "$DB_URL" up
```

### 4. Run the server

```bash
go build -o out && ./out
# or
go run .
```

The server listens on `http://localhost:8080`.

### Regenerating database code

After editing files in `sql/queries/` or `sql/schema/`:

```bash
sqlc generate
```

### Running tests

```bash
go test ./...
```

## API Reference

All JSON errors look like this:

```json
{ "Error": "message" }
```

Authenticated endpoints expect an `Authorization` header:

- **Access token:** `Authorization: Bearer <jwt>`
- **Refresh token:** `Authorization: Bearer <refresh_token>`
- **Polka API key:** `Authorization: ApiKey <key>`

### Endpoints

| Method   | Path                  | Auth          | Description                          |
| -------- | --------------------- | ------------- | ------------------------------------ |
| `GET`    | `/api/healthz`        | —             | Health check, returns `OK`           |
| `POST`   | `/api/users`          | —             | Create a user                        |
| `PUT`    | `/api/users`          | Access token  | Update your email and password       |
| `POST`   | `/api/login`          | —             | Log in and get an access token and a refresh token |
| `POST`   | `/api/refresh`        | Refresh token | Get a new access token               |
| `POST`   | `/api/revoke`         | Refresh token | Revoke a refresh token               |
| `GET`    | `/api/chirps`         | —             | List chirps                          |
| `GET`    | `/api/chirps/{id}`    | —             | Get one chirp                        |
| `POST`   | `/api/chirps`         | Access token  | Create a chirp                       |
| `DELETE` | `/api/chirps/{id}`    | Access token  | Delete your own chirp                |
| `POST`   | `/api/polka/webhooks` | Polka API key | Upgrade a user to Chirpy Red         |
| `GET`    | `/admin/metrics`      | —             | HTML page showing file server hits   |
| `POST`   | `/admin/reset`        | —             | Reset hits and delete all users (`PLATFORM=dev` only) |
| `GET`    | `/app/*`              | —             | Static files                         |

### Users

**`POST /api/users`** → `201 Created`

```json
// request
{ "email": "walt@breakingbad.com", "password": "123456" }

// response
{
  "id": "50746277-23c6-4d85-a890-564c0044c2fb",
  "created_at": "2026-10-01T00:00:00Z",
  "updated_at": "2026-10-01T00:00:00Z",
  "email": "walt@breakingbad.com",
  "is_chirpy_red": false
}
```

**`PUT /api/users`** → `200 OK`. It takes the same request body and returns the updated user.

**`POST /api/login`** → `200 OK`

```json
// request
{ "email": "walt@breakingbad.com", "password": "123456" }

// response
{
  "id": "...",
  "created_at": "...",
  "updated_at": "...",
  "email": "walt@breakingbad.com",
  "is_chirpy_red": false,
  "token": "<jwt access token>",
  "refresh_token": "<refresh token>"
}
```

### Tokens

**`POST /api/refresh`** → `200 OK`

```json
{ "token": "<new jwt access token>" }
```

**`POST /api/revoke`** → `204 No Content`

### Chirps

**`POST /api/chirps`** → `201 Created`

```json
// request
{ "body": "I'm the one who knocks!" }

// response
{
  "id": "...",
  "created_at": "...",
  "updated_at": "...",
  "body": "I'm the one who knocks!",
  "user_id": "..."
}
```

- A body longer than 140 characters returns `400 Bad Request`.
- The words `kerfuffle`, `sharbert`, and `fornax` are replaced with `****`, ignoring case.

**`GET /api/chirps`** → `200 OK` with an array of chirps.

| Query param | Values           | Default | Description                     |
| ----------- | ---------------- | ------- | ------------------------------- |
| `author_id` | user UUID        | —       | Only return this user's chirps  |
| `sort`      | `asc` \| `desc`  | `asc`   | Sort by `created_at`            |

```bash
curl "http://localhost:8080/api/chirps?author_id=<uuid>&sort=desc"
```

**`GET /api/chirps/{id}`** → `200 OK`, or `404 Not Found` if the chirp does not exist.

**`DELETE /api/chirps/{id}`** → `204 No Content`. It returns `403 Forbidden` if the chirp belongs to another user and `404 Not Found` if it does not exist.

### Webhooks

**`POST /api/polka/webhooks`** → `204 No Content`

```json
{
  "event": "user.upgraded",
  "data": { "user_id": "..." }
}
```

Events other than `user.upgraded` are acknowledged with `204` and ignored. A missing or wrong API key returns `401`, and an unknown user returns `404`.

## Example Session

```bash
# Sign up
curl -X POST localhost:8080/api/users \
  -d '{"email":"walt@breakingbad.com","password":"123456"}'

# Log in and save the access token
TOKEN=$(curl -s -X POST localhost:8080/api/login \
  -d '{"email":"walt@breakingbad.com","password":"123456"}' | jq -r .token)

# Post a chirp
curl -X POST localhost:8080/api/chirps \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"body":"Hello, Chirpy!"}'

# List chirps, newest first
curl "localhost:8080/api/chirps?sort=desc"
```
